# 東京都 本免学科試験 キャンセル空席監視システム

府中・鮫洲・江東の3試験場について、本免学科試験（教習所卒業等 → 免許証のみ）の
予約カレンダーを5分間隔で自動巡回し、残席が **0名 → 1名以上** に変化した瞬間を検知して
Discord（お使いのスマートフォンの Discord アプリ）に通知します。

**予約の自動化は行いません。** 空席を検知して通知するところまでが役割です。
通知を受け取ったら、ご自身でサイトを開いて手動で予約してください。

---

## 0. 事前に知っておいてほしいこと（重要・正直な説明）

このシステムを作るにあたり、対象サイトの実際の画面遷移・API通信を、私（Claude）の作業環境から
直接確認することができませんでした。理由は次の2点です。

1. 対象サイトは JavaScript がないと動作しない SPA（単一ページアプリ）で、
   静的HTMLやAPIを直接GETしても中身が取得できないことを確認済みです（robots.txt は存在せず404）。
2. 私が作業しているクラウド環境はセキュリティ上ネットワークアクセスが制限されており、
   対象サイトへ実際に接続してブラウザで動作確認することができません
   （実際に Playwright で接続を試みたところ `ERR_TUNNEL_CONNECTION_FAILED` で失敗することを確認済みです）。

そのため本スクリプトは、あなたが説明してくださった画面遷移
（① 受験する項目を選択 → ②「教習所卒業等」→ ③「免許証のみ」→ ④ 試験場選択 → ⑤ カレンダー →
⑥ 日付選択 → ⑦ 午前/午後の残席表示）に忠実に沿って作ってありますが、
実際のボタンや日付セルの内部構造（HTML/CSS）に対しては

- テキストの内容（「教習所卒業等」「免許証のみ」「府中試験場」等）で要素を探す
- カレンダーの日付セルは複数の一般的なパターンで探す

という**柔軟な探し方**をする作りにしてあります。多くの場合はこれで動きますが、
**初回実行時にうまく要素が見つからない可能性があります**。そのための仕組みとして:

- `DEBUG=1` で実行すると各ステップのスクリーンショットとHTMLを `artifacts/` に保存します
- GitHub Actions では手動実行（workflow_dispatch）時に debug オプションを ON にできます
- 見つからなかった場合はエラーとして処理を打ち切らず、ログに残して次の試験場へ進みます

**もし初回実行がうまくいかなかった場合は、GitHub Actions の実行ログと
debug artifacts（screenshots/html）をダウンロードしてこの会話に貼っていただければ、
実際のDOM構造に合わせてセレクタを調整します。**

## 1. 全体構成

```
config.py        設定値（試験場名、URL、監視間隔などはここを見れば全部わかる）
scraper.py        メインの監視スクリプト（Playwright）
state_store.py     重複通知防止のための状態管理（state.json）
notify.py          Discord Webhook への通知
state.json         前回チェック結果（初回は空。Actionsが自動更新してリポジトリにコミットする）
test_logic.py       ネットワーク不要の単体テスト（パース処理・重複防止ロジック）
requirements.txt    依存パッケージ
.github/workflows/monitor.yml   GitHub Actions のスケジュール実行設定（5分間隔）
```

`test_logic.py` はこちらの環境で実行済みで、**6件のテストすべて成功**しています
（残席テキストの解析、0→1以上の遷移検知、重複通知防止、予約確定ボタンを誤ってクリックしない安全策）。
ただし実サイトのDOM操作部分（`collect_venue_results` 関数）は前述の理由により未検証です。

## 2. セットアップ手順

### 2-1. GitHubリポジトリを作る
1. https://github.com にログイン（アカウントがなければ無料で作成）
2. 右上の「+」→「New repository」
3. Repository name は任意（例: `license-cancel-watch`）、**Private推奨**（公開する必要はありません）
4. 「Create repository」

### 2-2. このフォルダの中身をアップロード
一番簡単な方法は、リポジトリ画面の「Add file」→「Upload files」から、
このZIPの中身（`config.py` や `scraper.py` など）を**フォルダ構造を保ったまま**ドラッグ&ドロップし、
「Commit changes」することです。
（`.github/workflows/monitor.yml` のパスが崩れないよう注意してください。GitHubのアップロードUIは
フォルダごとドラッグすると構造を保ってくれます。）

Gitに慣れている場合はコマンドでも構いません:
```bash
cd license-cancel-watch
git init
git add .
git commit -m "init: license cancel watch"
git branch -M main
git remote add origin https://github.com/<あなたのアカウント>/license-cancel-watch.git
git push -u origin main
```

### 2-3. Discord Webhook URL を発行する
1. 通知を受け取りたい Discord サーバー（なければ自分専用のサーバーを新規作成）で、
   通知用のテキストチャンネルを1つ作る（例: `#免許試験通知`）
2. チャンネル設定（歯車アイコン）→「連携サービス」→「ウェブフック」→「新しいウェブフック」
3. 名前を適当に付けて「ウェブフックURLをコピー」
4. スマートフォンの Discord アプリで通知がオンになっていることを確認（アプリの通知設定）

### 2-4. GitHub 側に Webhook URL を Secret として登録する
1. リポジトリの「Settings」→「Secrets and variables」→「Actions」
2. 「New repository secret」
3. Name: `DISCORD_WEBHOOK_URL`
4. Secret: 2-3でコピーしたURLを貼り付け
5. 「Add secret」

### 2-5. Actions を有効化する
1. リポジトリの「Actions」タブを開く
2. 「I understand my workflows, go ahead and enable them」をクリック（表示された場合）
3. 左側の「本免学科試験キャンセル監視」ワークフローを選択
4. 「Run workflow」で手動実行し、まずは動作確認する
   - このとき `debug` を `true` にしておくと、うまくいかなかった箇所のスクリーンショットが
     Artifacts に残るので原因調査がしやすくなります

これで完了です。以降は `cron` 設定により**5分間隔**で自動実行されます。

## 3. 動作の仕組み（重複通知防止）

`state_store.py` が試験場・日付・午前午後ごとに前回の残席数を `state.json` に記録します。

- 残席が **0 → 1以上** になった瞬間だけ通知します
- 空きが続いている間（1→3→2など）は再通知しません
- 再び 0名 に戻ると「通知済みフラグ」がリセットされ、次に空きが出たときはまた通知します

`state.json` は毎回の実行後、GitHub Actions が自動でリポジトリにコミット・プッシュして
次回の実行に引き継ぎます。

## 4. サイトへの配慮について

- 対象サイトに `robots.txt` は存在しませんでした（クロール可否の明示的な記載なし）
- 警視庁の案内ページには「多重予約など不正利用への対応」の記載はありましたが、
  読み取り専用の自動巡回そのものを明示的に禁止する記載は見つけられませんでした
  （利用規約の全文までは確認できていないため、可能であればご自身でも一度目を通すことをお勧めします）
- そのため下記の配慮をした設計にしてあります
  - 3試験場は**同時並列ではなく順番に**アクセス（負荷を分散）
  - 各操作の間に待機時間を挿入（`ACTION_DELAY_SEC` / `VENUE_DELAY_SEC`）
  - 監視間隔は5分（GitHub Actions cronの実用上の最短単位。実際には数分の遅延が起きることがあります）
  - 予約操作（申込・確定ボタン）は**コード上で明示的に禁止**（`FORBIDDEN_BUTTON_TEXT_HINTS` に
    一致するテキストは絶対にクリックしない安全策を入れています）
- もしサイト側からアクセス制限やエラーが頻発するようになった場合は、
  `config.py` の `ACTION_DELAY_SEC` / `VENUE_DELAY_SEC` を増やすか、
  cron の間隔を10〜15分に緩めてください。運用開始後に何らかの警告が出た場合は速やかに停止してください。

---

## 5. 通知の停止方法

- 一時停止: リポジトリの Actions タブ →「本免学科試験キャンセル監視」→「...」→「Disable workflow」
- 完全に削除: `.github/workflows/monitor.yml` を削除、またはリポジトリごと削除

## 6. 既知の制約・今後の調整ポイント

- 日付の年月をカレンダー見出しから読み取る部分（`extract_current_date_label`）は
  見出しのマークアップが不明なため簡易実装です。うまく年月が取れない場合、実行日基準で概算します。
  実際のログ・artifactsを見て調整が必要な場合があります。
- 「翌月へ」ボタンの文言も候補をいくつか試す作りですが、実際の表記が候補外だった場合は
  最初の月しか見に行きません。
- これらはいずれも **debug artifacts を見せていただければ実データに合わせて確実に修正できます。**
